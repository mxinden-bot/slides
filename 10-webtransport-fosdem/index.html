Where WebSocket sits

  • WebSocket rides on top of HTTP, so it inherits HTTP’s transport.
  • On HTTP/1 and HTTP/2 that means TCP; on HTTP/3 it would mean QUIC.

Browser support today: HTTP/1 and HTTP/2 only.

WebSocket upgrade  1-RTT

  • A short handshake turns an HTTP connection into a WebSocket, mostly one round trip.
  • Sending data optimistically (0-RTT) is not safe on HTTP/1 (draft-ietf-httpbis-optimistic-upgrade).

Introducing WebTransport

  • A new Web API, an ongoing effort at the IETF and W3C.
  • Focus on HTTP/3, with a fallback on HTTP/2.
  • Fine-grained flow control per session.
  • Independent reliable streams and unreliable datagrams.
  • No head-of-line blocking on the session or the transport.

WebTransport use cases

  • Cloud gaming & remote desktop: user input (reliable) while receiving high-frequency video and state (unreliable).
  • Live streaming: pushing media chunks to a server with low overhead.
  • Collaborative editing: cursor positions (unreliable) while document changes (reliable) are persisted.
  • Internet of Things: multiplexing sensor data from thousands of devices.
  • Financial tickers: high-frequency market data where the latest packet matters most.

Source: WebTransport explainer.

Where WebTransport sits

  • WebTransport is built on HTTP/3, and therefore on QUIC.
  • An HTTP/2 fallback is defined for paths where QUIC does not get through.

What QUIC and HTTP/3 bring

  • A general-purpose transport on top of UDP, with encrypted (meta)data.
  • 1-RTT connection setup, 0-RTT on resumption.
  • Reliable streams and unreliable datagrams, with no head-of-line blocking.
  • Connection migration across network changes.
  • Easy to evolve, often in user space.

HTTP/3 adoption

WebTransport upgrade  0-RTT capable

  • An extended HTTP CONNECT opens the session.
  • On a resumed QUIC connection, the client can send stream data and datagrams immediately, without waiting for the response.

  • QUIC tracks delivery per stream, so a loss on stream B stalls only stream B.
  • Stream A is delivered on time, and unreliable datagrams are never held back at all.
  • That removes the blocking at both the session and the transport level.

Status at W3C and IETF

W3C

  • Draft, going to wide review for Candidate Recommendation soon.

IETF

  • Over HTTP/3: draft 14.
  • Over HTTP/2: draft 13.
  • No major changes expected.

Who is using it?

  • Low adoption so far.
  • The emerging consumer is Media over QUIC (MoQ): a simple, low-latency media delivery solution for ingest and distribution.
  • Targets live streaming, gaming and conferencing, in browser and non-browser endpoints.

Source: IETF Media over QUIC (moq) working group.
