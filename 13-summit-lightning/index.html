HTTP everywhere

  • HTTP is the thin waist of the Internet: consistent, extensible, a strong security model, hard to censor.
  • More and more runs over it:
    • DNS: DNS over HTTPS
    • Web apps’ own protocols: WebTransport
    • Proxied TCP and UDP: MASQUE

HTTP is the thin waist, and we keep putting more on top of it: DNS, web apps, proxying.

QUIC and HTTP/3  0-RTT

  • Transport on UDP, encrypted down to the packet headers.
  • 1-RTT connection setup, 0-RTT on resumption: the request goes out with the first packet.
  • No head-of-line blocking between streams.
  • Our QUIC stack is neqo, in Rust.
  • About 30% of Firefox requests use HTTP/3, in line with Cloudflare.
About a third of our traffic is HTTP/3 already. 0-RTT: on a repeat visit the request goes out with the handshake.

Happy Eyeballs v3

  • Race IPv4 and IPv6, TCP and QUIC, A, AAAA and HTTPS records: take whatever connects first.
  • A sans-I/O Rust library: mozilla/happy-eyeballs.
  • Follows the IETF draft draft-ietf-happy-happyeyeballs-v3.
  • On in Nightly, rolling out on Beta and Release.
  • With DoH, +68% page loads over HTTP/3.
One state machine decides how to connect. The Beta experiment shows the win: far more HTTP/3, most of all with DoH.

HTTPS records and ECH

  • The DNS HTTPS record (RFC 9460) says “speaks HTTP/3” before we connect. Alt-Svc only tells us after a first HTTP/2 connection.
  • It also carries the key for Encrypted Client Hello (ECH), which hides the server name. ~16% of HTTPS records carry one (GLAM).
  • Check a domain: savearoundtrip.com.
  • DNS over HTTPS: see Valentin’s talk.
Most sites announce HTTP/3 only via Alt-Svc, which costs a round trip on first visit. HTTPS records fix that and enable ECH. DoH: Valentin.

WebTransport and MASQUE

  • WebTransport: streams and datagrams for web apps, over HTTP/3. In all major browsers since March 2026; W3C Candidate Recommendation.
  • MASQUE: proxy TCP (CONNECT) and UDP (RFC 9298) through HTTP/3.
  • Firefox’s built-in IP protection proxies over HTTP/2 CONNECT today. HTTP/3 and UDP proxying work end to end, but are not yet as fast (bug 1978893).
Both build on HTTP/3. MASQUE is how we want to proxy; the UDP path still needs performance work.

When the network interferes

InterferenceFirefox’s answer
Censorship
Filtering on the server name (SNI).SNI slicing in QUIC: split and reorder the ClientHello across packets (neqo#2228). ECH encrypts the name.
Tampering with DNS.DNS over HTTPS (Valentin’s talk).
Bad networks, antivirus, enterprise “security”
Firewalls block UDP, so QUIC fails.Happy Eyeballs races QUIC against TCP: a blocked path costs a short delay, not an error.
Black holes: ECN marks stripped on 38% of QUIC paths, ECN-marked packets dropped on 2% (GLAM).neqo validates ECN per path and stops marking where it fails.
“Security” software mangles QUIC: Avast crashed neqo with a bogus ACK (bug 1919678), Bitdefender broke Facebook (bug 2034178), CrowdStrike dropped crypto frames (bug 1990699), Kaspersky sent a bogus TLS alert (bug 1990210).Harden neqo (close, don’t crash), fall back to HTTP/2, and roll back what trips them (neqo#3573).
Censors: SNI slicing and ECH, DoH for DNS. Bad networks and "security" software: race and fall back, validate ECN, and harden neqo. Users blame the browser, not the middlebox.
