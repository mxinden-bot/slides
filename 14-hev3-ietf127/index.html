A reusable library: mozilla/happy-eyeballs

  • Rust, deterministic, sans-I/O: no network, no clock. The caller drives the I/O and passes time in.
  • Every scenario is a plain unit test.
  • Version 2.0.0, 3 November 2026.
  • New: an HTTPS record with an IP hint for the preferred family counts as that family’s answer, so the race starts without waiting for AAAA (#153, per draft §4.2.1).

Release experiment

Firefox 160, first results.

Setup

  • Firefox Desktop Release, version 160. Two branches, 5% of users each, about 1.17M clients per branch.
  • Control: Happy Eyeballs v3 off. Treatment: Happy Eyeballs v3 on.
  • The treatment also doubles the DNS cache (1600 to 3200 entries), so results show both changes together.
  • Page loads from 5 to 13 November 2026 whose main document opened a new connection: about 23% of all page loads, 5.2M (control) and 5.4M (HEv3).

First contentful paint is faster at every percentile

Real-world edge cases

  • DNS negative answers: honour the SOA-derived negative TTL (RFC 2308, bug 2049173), and do not re-resolve them mid-race (bug 2049178).
  • DNS coalescing: a v4-only or v6-only lookup could not reuse a pending AF_UNSPEC lookup (bug 2044254).
  • Multi-CDN: a non-standard HTTPS-RR/CNAME consistency check rejected legitimate multi-CDN records; now each TargetName resolves independently (RFC 9460 §10.4.4, #104).
  • Web standards: dnsLookupEnd stopped matching Resource Timing (bug 2047648).

Tracked in the Happy Eyeballs v3 meta bug.
