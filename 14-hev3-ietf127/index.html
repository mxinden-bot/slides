Changes since IETF 126

  • An HTTPS record with an IP hint for the preferred family counts as that family’s answer, so the race starts without waiting for AAAA (happy-eyeballs#153, draft §4.2.1).
  • Firefox implements Optimistic DNS: connect to a stale answer right away while a fresh lookup runs. Fresh addresses join the same race, so a stale address that no longer works does not fail the connection (bug 2060788).
  • Stale negative answers are revalidated too (bug 2072592). They get the same 600 s grace period as positive ones (bug 2084330).

What Happy Eyeballs will enable in the future

DNS

  • Optimistic DNS done bug 2060788
    Race a stale answer, revalidate in parallel.
  • Network change proposed bug 2091374
    Mark DNS cache entries stale instead of deleting them.
  • Persistent DNS cache proposed bug 2087407
    Keep answers and HTTPS records across restarts.

HTTP/3

  • Optimistic Alt-Svc proposed bug 2060496
    Reuse an expired HTTP/3 Alt-Svc mapping.
  • Optimistic HTTP/3 proposed bug 1914201
    Race QUIC with no prior HTTP/3 signal.
  • Proxies proposed bug 2071358
    Race HTTP/3 against HTTP/2 through the proxy tunnel.
