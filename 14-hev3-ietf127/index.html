Firefox’s delays are now in the draft

Resolution Delay

  • Recommended: 25 ms, was 50 ms (#148).

Connection Attempt Delay Multiplier

  • New, optional. A 50 ms base with a ×2 multiplier starts attempts at 0, 50, 150, 350 and 750 ms (#143).

Release experiment

Firefox 160, first results.

Setup

  • Firefox Desktop Release, version 160. Two branches, 5% of users each, about 1.17M clients per branch.
  • Control: Happy Eyeballs v3 off. Treatment: Happy Eyeballs v3 on.
  • 5 to 13 November 2026.
  • Only page loads whose main document opened a new connection: about 23% of all page loads. That is where Happy Eyeballs acts.

Changes since IETF 126

  • An HTTPS record with an IP hint for the preferred family counts as that family’s answer, so the race starts without waiting for AAAA (happy-eyeballs#153, draft §4.2.1).
  • Firefox implements Optimistic DNS: race a stale answer right away, revalidate with a lookup that bypasses the cache, and race the fresh answer too (bug 2060788).
  • Stale negative answers are revalidated too (bug 2072592). They get the same grace period as positive ones (bug 2084330) and a 300 s cache lifetime (bug 2084328).
